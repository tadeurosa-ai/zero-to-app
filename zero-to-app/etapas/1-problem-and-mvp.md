# Stage 1 — Problem and MVP

Goal: make sure there is a real problem and shrink the idea to the smallest version that already solves it.
Building the wrong thing is the most expensive beginner mistake, and it costs nothing to avoid it here.

1. **Back to the problem.** If the person arrives with a solution ("an app that does X"), go back to the problem,
   one question per message: who has it → how they solve it today → what bothers them about that.
2. **"Does it really need to be an app?"** Sometimes a spreadsheet, a form or a message group tests the idea
   faster. Say so honestly; if an app is still the best path, continue.
3. **Three blind spots** (one question each):
   - What must never be touched or broken (real data, someone else's account, money)?
   - What can be undone, and what can't?
   - Who can see what?
4. **MVP = 1 user, 1 action, 1 result.** Example: "a nail salon client books a time slot and gets a
   confirmation". Everything else waits.
5. **If it's for other people or to sell:** friends and family don't count as proof — they say yes to be nice.
   Define the test goal *before* building (for example, "5 people I don't know use it twice in one week" or
   "3 people pay").
6. **Hypothesis + cheap test:** "I believe that [who] will [do what] because [why]. I'll test it by [cheapest way]."
7. **Confirmation sentence** — the person confirms or corrects:
   "For [who], my app lets them [action] to get [result]. I'll know it works when [test goal]."
8. **Decision: continue / change / abandon.** Abandoning an idea that didn't hold up is a good result — it saved
   weeks. Recommend one of the three, with the reason.

Close: acknowledge the progress, ask "Any questions?", save WHERE I STOPPED if the conversation is long, then
stage 2.
